# BranchQuest theme system

The theme is a presentation preference. It does not change graph reachability, course/degree data, filtering, additions, marks, credit totals, feedback submission or SEO page identities.

## Preference and first paint

`src/lib/theme-bootstrap.ts` is the single source of the early controller and the `branchquest.theme` storage key. Its only saved values are `light` and `dark`. Without a valid explicit choice, it follows `prefers-color-scheme`, including subsequent operating-system changes. An explicit choice wins until changed or removed. Same-origin tabs synchronize theme changes through the normal storage event. Progress-key changes are ignored. Storage failures are caught; the choice still works for the current document when persistence is unavailable.

The SEO plugin injects this exact script into the HTML head before the linked CSS, in both Vite development and production. It sets `html[data-theme]` and the browser theme-color before content can paint. React does not own the document element, so hydration remains identical to the server HTML. The shared toggle contains both moon and sun presentations; CSS selects the matching icon and Hebrew action name even before React loads. One delegated native click listener handles mouse, touch and keyboard-generated button clicks, including the pre-rendered header. No React graph state is subscribed to theme changes.

`vercel.json` allows the exact bootstrap SHA-256 alongside the existing JSON-LD hash. Arbitrary inline scripts and inline event-handler attributes remain blocked. There is no external theme service, extra blocking theme request, inline-script wildcard, new dependency or new environment variable. `npm run build` checks that the bootstrap source, generated HTML order and CSP hash agree. When deliberately editing the bootstrap, update its exact CSP hash and run the checks; never add `unsafe-inline` to script-src.

The binary toggle is beside feedback in the explorer header and is also available in About/feedback headers. On phones narrower than 360px the existing help action uses its question-mark icon with the same accessible Hebrew name, providing space for all three controls. Header height and the graph area are preserved.

## Color architecture

`src/theme.css` defines the coordinated charcoal surfaces, primary/secondary/muted text, purple fills and accents, borders/focus, shadows/overlays, success/warning/marking states and graph colors. The existing styles and tutorial styles consume these semantic tokens. Their exact old light literals remain fallbacks rather than being flattened into a different light palette. There is no filter-based inversion or second copy of the entire stylesheet. New theme rules introduce no `!important` declarations.

Tokens live on the document element, covering body portals as well as normal descendants. React Flow integration uses its own CSS custom properties; course edges, arrowheads and dots resolve stable CSS-variable colors. Theme changes do not rebuild the graph or change connection identifiers. Course details, marked lists, branch controls, search overlays, native form controls, filters, mobile tools, tutorial examples, public pages, loading shells and footer all share the same palette. `color-scheme` also informs browser-native controls.

The original twelve light faculty colors and ownership rules are unchanged. `facultyDisplayColor()` is a rendering-only, allowlisted CSS-variable reference. A separate twelve-color dark palette is necessary because several original dark faculty tones have insufficient contrast on charcoal. Dark labels are checked at 4.5:1 or better on their actual six-percent tinted card surface; palette pairs have a minimum OKLab distance of 0.04, and each stays at least 0.1 from the marked-red accent. These checks are regression budgets, not a guarantee that every user perceives all colors equally. Faculty names, relationship badges, checks and other non-color cues remain present.

Marked courses use a separate bright red border, subtle dark red surface and a darker red filled checkbox with a readable white check. Added badges remain purple and independent. Concurrent cards retain their neutral tint and text badge. Backward exploration retains green controls/dashed arrows/קדם; prerequisite-satisfaction rings retain their check indicator. None of these change academic or prerequisite logic.
